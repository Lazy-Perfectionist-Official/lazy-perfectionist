# 📅 2026-11-06 - The Lens

**Author**: Samuel Lee
**Category**: 🎨 Design

## 🎯 Overview

After the lantern, the ask was for a *distortion* on the fold — *"how about we
follow with a subtil tile and distortion at the cursor?"* — and then, before it
was finished, that the shape be alive: *"make it not a static circle but the
circle will deform depending where the velocity the mouse is moving."* And,
once the effect existed at all, that it not stall when the page moves: *"it
needs to work even when scrolling down."*

So the fold now carries a lens as well as a light, both drawn at the same two
custom properties the lantern script writes. The lens is the same plate a hair
magnified, masked to a feathered circle at the cursor; the circle's shape is
driven by the pointer's speed.

## 🔍 The effect

- **A copy, never a filter.** The distortion is a second `next/image` of the
  same plate under a feathered mask, not an SVG filter or a `filter` on the
  image that paints the fold. The plate is the LCP and stays untouched: it is
  painted whole, first frame, exactly as before. The copy shares the plate's
  `src` and orientation-scoped `sizes`, so it costs no extra bytes — the
  browser serves it from cache.
- **Magnified a hair, and no more.** 1.2% about the pointer. Tried at 3.5% and
  7% first: both showed a second edge a few pixels off on *Lazy Perfectionist*
  — a smudge, not glass. At 1.2% the magnify is below the threshold where a
  600px Bodoni stem reads as doubled, and the lens is still there.
- **The circle deforms, the print does not.** The speed is not measured with a
  timer: the light already trails the pointer at 12% a frame, so *how far the
  eased centre is behind the target* is the pointer's speed. That gap, eased
  over, becomes `--lens-k` (0…1). At rest the drop is a circle; at speed it
  becomes an oval — stretched 8% along the direction of travel, thinned 6%
  across it, turned about the pointer by `--lens-angle`.
- **The print under the glass counter-transforms.** Applying that stretch to
  the lens layer stretches its image too, and 6% of a lens radius is a visible
  double impression of the type (measured: an obvious smear across
  "Perfectionist" at k = 0.8). So the span is the **glass** and the image
  inside it is the **print**: the span takes the deformation, the image takes
  the exact inverse (`--lens-isx/isy`, written by the script), and the two
  compose back to the resting 1.2% enlarge at any speed. Only the circle's
  shape breathes. A test asserts the composition, so a future tweak cannot
  quietly reintroduce the smear.
- **It keeps up while the page scrolls.** The script keeps the last *screen*
  point and re-reads the fold's box on `scroll` as well as on `pointermove`.
  The fold slides up under a pointer that has not moved, so the light slides
  with the print — and it stays lit while it is over the fold, which the old
  `pointerenter`-only version did not. Scrolling with the wheel therefore also
  stretches the drop, along the scroll direction, which is the effect doing
  what it was asked to do.

## 🧵 The script

Still the site's only hand-written script, still gated on
`(hover: hover) and (pointer: fine)` and `prefers-reduced-motion`,
`pointermove` and `scroll` both passive, still one self-stopping
`requestAnimationFrame` loop. It now writes four more properties:
`--lens-k`, `--lens-angle`, `--lens-isx`, `--lens-isy`. `pointerenter` was
replaced by an inside-the-box check on every aim, so a fold that scrolls under
a still pointer lights, and one that scrolls out of it goes dark.

Under reduced motion the lens is `display: none` alongside the lantern, and on
touch it is never lit: the fold remains the still print.

## 🧪 Verified

- **No double impression.** The two transforms compose to
  `matrix(1.012, 0, 0, 1.012)` at k = 0.79 (lens 1.0623 × plate 0.9527), and the
  mid-swipe screenshot over "Perfectionist" is clean where the same shot before
  the counter-transform was smeared.
- **The deformation is real, not decoration.** Frame diff at k = 1 against
  k = 0 over the same pointer position: **peak 21/255, mean 0.5** — comparable
  to the lantern's own presence (24/255 peak).
- **Scrolling.** Pointer held still at 30% of the fold, wheel 240px: `--lantern-y`
  follows to 55%, the pool stays lit.
- `npx tsc --noEmit`, `npm run lint`, `npm run lint:css` — clean.
- `npm run test:pipeline` — **74 passed, 4 skipped** (chromium / firefox /
  webkit); `home.spec.ts` across all four projects: **93 passed, 7 skipped**;
  `npm run test:mobile` — **23 passed, 3 skipped** (the pointer tests skip on
  a touch screen).
- New tests: *the drop deforms with the pointer and rounds off at rest*
  (k > 0.3 mid-flick, glass stretched, composed transform ≈ 1.012 with no skew,
  k < 0.05 at rest) and *the light keeps up while the page scrolls*; the
  reduced-motion test now also asserts the lens is `display: none`.
